# Архитектурное видение: PoB2.NET (C# 15 / .NET 11 + LuaJIT Worker)

> **Статус документа:** Стратегический ориентир (Future Architecture RFC / Roadmap).  
> **Дата фиксации:** 2026-11-11  
> **Приоритет на текущий момент:** Отложен до завершения стабилизации текущего рабочего приложения PoB2 (SimpleGraphic + Lua).

---

## 1. Суть концепции

Вместо рискованного и трудоёмкого полного переписывания математики Path of Building на C# или Rust, предлагается **гибридная двухконтурная архитектура**:
* **Клиентский контур (Frontend & Host):** C# 15 / .NET 11 (WinUI 3 для Windows или Avalonia UI для кроссплатформенности). Отвечает за интерфейс, UX, оконную систему, плагины, сеть, локализацию UI и аппаратный рендеринг дерева пассивных умений.
* **Вычислительный контур (Backend Engine):** Оригинальный **LuaJIT 2.1**, работающий в виде фонового постоянного процесса (**Persistent Worker**).
* **Связующий слой (Bridge):** Развитие `src/HeadlessWrapper.lua` в версионированный протокол обмена DTO (JSON Lines / MessagePack через IPC / стандартные потоки stdin/stdout).

---

## 2. Анализ технологического стека оригинального PoB2

1. **SimpleGraphic — это не просто окно:**
   * Это нативная среда исполнения Lua на C++23 (OpenGL ES 2.0 / ANGLE / GLFW / ImGui / fmtlib / RE2 / libcurl / zlib / zstd).
   * Реализует: оконную систему, ввод клавиатуры/мыши, буфер обмена, таймеры, загрузку картинок, субпроцессы и FFI.
   * Полная замена SimpleGraphic — это замена всей платформы хостинга скриптов, а не только графики.
2. **Критическая зависимость от LuaJIT:**
   * Используются `jit.opt.start`, FFI-массивы (`runtime/lua/sha2.lua`) и специфичные расширения Lua 5.1 / LuaJIT.
   * Замена на стандартный Lua (5.4 / 5.5) приведёт к несовместимости с апстримом. LuaJIT 2.1 обязателен.
3. **HeadlessWrapper.lua — точка опоры:**
   * В апстриме уже есть запуск без графики (`newBuild()`, `loadBuildFromXML()`, `loadBuildFromJSON()`).
   * Требуется доработка: реализация отсутствующих нативных заглушек (`Deflate`/`Inflate`), фоновых задач и стабильного API мутации состояния билда.

## 3. Матрица разделения ответственности (Что переносить, а что оставить)

| Компонент | Среда / Язык | Обоснование |
| :--- | :---: | :--- |
| **CalcEngine** | LuaJIT | Сохранение 100% математической точности и формул урона |
| **ModDB / ModParser** | LuaJIT | Постоянные обновления механик PoE2 разработчиками GGG |
| **Skills / Items / Crafting** | LuaJIT | Прямая совместимость с апстримом PoB2 без задержек |
| **Build Model / State** | Адаптер (Lua + C#) | DTO-контракты для сериализации/десериализации |
| **Passive Tree Renderer** | C# (Win2D / Skia) | Профилирование показало узкое место в отрисовке связей; C# даст 60+ FPS, BVH-индексацию и плавный зум |
| **Application UI** | C# 15 / .NET 11 | Современный адаптивный UI, нормальный DPI-скейлинг, accessibility |
| **Network & Updater** | C# | Безопасная загрузка через .NET `HttpClient`, SHA-256, атомарные патчи |
| **Data Tools / GGPK** | Rust (отдельная CLI) | Проверка целостности DAT-файлов, аудит diff между патчами |
| **Скрипты анализа** | Python 3.10+ | Автоматизация аудита неподдерживаемых модов, регрессионные отчёты |

## 4. Архитектура изоляции (IPC Worker)

```
┌────────────────────────────────────────────────────────┐
│               PoB2.NET (C# 15 / .NET 11)              │
│  Desktop UI (WinUI 3 / Avalonia)                       │
│  Passive Tree Hardware Renderer (Direct2D / SkiaSharp) │
│  Plugin Host & Settings Manager                        │
└───────────────────────────┬────────────────────────────┘
                            │
               IPC (JSON Lines / MessagePack)
               stdin / stdout (Persistent Pipe)
                            │
┌───────────────────────────▼────────────────────────────┐
│                  PoB2 Lua Worker Host                  │
│  Минимальный C++23 native launcher + LuaJIT 2.1 DLL    │
│  BridgeHost.lua (расширение HeadlessWrapper.lua)       │
├────────────────────────────────────────────────────────┤
│  Оригинальное вычислительное ядро PoB2:                │
│  - CalcEngine       - ModParser        - Items         │
│  - ModDB            - Skills           - TreeData      │
└────────────────────────────────────────────────────────┘
```

**Преимущества изоляции:**
1. Никаких нестабильных прямых P/Invoke в сложные Lua-таблицы (GC leaks, pinning, потокобезопасность).
2. Сбой/крэш в стороннем Lua-скрипте изолирован и не роняет UI-процесс пользователя.
3. Полная независимость версий рантаймов.

## 5. Дорожная карта и поэтапный план

### Текущий приоритет: Фаза 0 (Текущая сборка)
* Завершить текущую стабилизацию форка PoB2 на стеке SimpleGraphic + Lua.
* Довести локализацию, поддержку кириллицы/шрифтов и UX-улучшения (Side-by-Side Tooltips, Compact Mode) до рабочего состояния.
* Получить надежный локальный **Ground Truth** эталон для будущих тестов совместимости.

### Фаза 1: Proof-of-Concept «PoB2.LuaBridge» (После стабилизации Фазы 0)
* Собрать минимальный автономный исполняемый `LuaWorkerHost` (C++23 + LuaJIT + zlib/miniz).
* Создать `BridgeHost.lua`, оборачивающий `HeadlessWrapper.lua`.
* Написать консольный C# PoC, отправляющий команду `LoadBuild` и замеряющий latency ответа и точность итоговых DPS/HP.

### Фаза 2: C# Passive Tree Renderer & Core Contracts
* Проектирование DTO-контрактов (`CharacterStats`, `PassiveTreeLayout`, `CalculationBreakdown`).
* Создание отдельного высокопроизводительного рендерера дерева умений с пространственным поиском узлов под курсором.

### Фаза 3: Полноценный UI и дифференциальное тестирование
* Реализация вкладок Tree, Skills, Items, Calcs на современном UI-фреймворке.
* Автоматизированный дифференциальный раннер: прогон сотен тестовых XML через оригинальный PoB2 и PoB2.NET со сверкой каждого числа.
