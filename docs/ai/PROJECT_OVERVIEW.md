# PoB2Fork — Project Overview

Дата начальной фиксации контекста: 2026-11-07.

## Цель

Развитие Path of Building Community PoE2 fork с русской локализацией,
улучшением пользовательского интерфейса и модернизацией связанных компонентов.

Проект использует несколько самостоятельных репозиториев и инструментов.
Их нельзя считать одним Git-репозиторием.

## Карта компонентов

### 1. PathOfBuilding-PoE2

Основное приложение Path of Building Community для Path of Exile 2.

Путь:
`PathOfBuilding-PoE2`

Это основной репозиторий приложения.

### 2. PathOfBuilding-SimpleGraphic

Графический компонент, связанный с отображением интерфейса.

Путь:
`PathOfBuilding-SimpleGraphic`

Ведётся отдельная работа над Unicode/Cyrillic rendering.
Изменения в C++ renderer необходимо рассматривать отдельно от Lua-кода приложения.

### 3. RePoE

Инструменты парсинга и экспорта данных Path of Exile 2.

Путь:
`PoE2-Localization-Extractor/RePoE`

Включает адаптации парсеров для извлечения ресурсов и локализационных данных.

### 4. PyPoE

Связанный инструментарий обработки данных Path of Exile.

Путь:
`PoE2-Localization-Extractor/PyPoE`

Самостоятельный Git-репозиторий.

### 5. PathOfExile_Translated

Ресурсы перевода Path of Exile.

Путь:
`PoE2-Localization-Extractor/PathOfExile_Translated`

Самостоятельный Git-репозиторий.

## Рабочие и вспомогательные каталоги

- `build-*` — сборки и результаты экспериментов.
- `*-stage*` — staging-каталоги.
- `*-relocated` — экспериментальные перемещения сборок.
- `Snapshots` — резервные копии.
- `PoE2-Localization-Extractor` — umbrella-каталог инструментов, не единый Git-root.

Не использовать экспериментальные каталоги как источник истины без проверки.

## Локализация

Разделять две задачи:

1. Контентная локализация игровых ресурсов PoE2.
2. Локализация интерфейса самого Path of Building.

Для контентной локализации важно сохранять стабильные идентификаторы оригинальных ресурсов.
Для интерфейса предпочтительна расширяемая система переводов без хаотичного хардкодинга.

## Общая архитектурная стратегия

- Сохранять независимость компонентов.
- Не смешивать изменения RePoE и основного приложения.
- Не менять контракты данных без изучения потребителей.
- Использовать воспроизводимые экспорты и валидаторы.
- Документировать решения, влияющие на совместимость.
- Сначала исследовать существующую архитектуру, затем выбирать масштаб рефакторинга.
