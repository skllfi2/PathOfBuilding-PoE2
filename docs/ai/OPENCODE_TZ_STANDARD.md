# Стандарт и шаблоны ТЗ для OpenCode / AI-агентов

Этот документ задаёт единый формат технических заданий (ТЗ) для локальных и облачных агентов (OpenCode, Antigravity и др.) на базе опыта разработки `PathOfBuilding-PoE2` (`D-033`..`D-050`).

---

## 1. Главные принципы хорошего ТЗ

1. **Изоляция расчётного ядра (Zero-Risk Rule):**
   - В каждом ТЗ явно указывать: **внутренние идентификаторы (`ModDB`, `output:*`, `item.baseName`, `gemData.id`, XML-ключи) не менять**. Перевод работает строго на display-слое.
2. **Конкретный список файлов (`Scope` и `Forbidden`):**
   - Перечислять точные пути, которые разрешено менять, и явно запрещать правку `CalcOffence.lua`, `CalcDefence.lua`, `ModParser*.lua` (кроме случаев, когда задача прямо про них).
3. **Технические ограничения среды (обязательно прописывать в ТЗ):**
   - **Кодировка:** UTF-8 **без BOM** (особенно для `.json`, `.lua`, `Settings.xml`).
   - **LuaJIT лимит:** не более 200 локальных переменных в одном файле/функции; крупные словари разбивать на чанки `<= 150` записей или хранить в таблице.
   - **Цветовые теги и плейсхолдеры:** сохранять `^7`, `^8`, `^xRRGGBB`, `\n`, `\t`, `%d`, `%.2f`, `%s`, `{0}` без искажений; не удваивать `%` (`%%`), если в оригинале один `%`.
   - **Бюджет ширины:** для левого сайдбара строка должна помещаться в `<= 180 px`, для меток контролов в диалогах/табах — в `<= 148 px`.
4. **Бэкапы до старта:**
   - Перед изменением любых существующих файлов копировать их в `Snapshots/<TaskName>-YYYYMMDD/` вне Git-истории.
5. **Измеримые критерии приёмки (Definition of Done):**
   - ТЗ завершается только после прогона конкретных скриптов в `host.exe` (`validate_ru_dicts.lua`, `verify_final_all.lua`, `calcs_check.lua` и целевых тестов) с `ERRORS=0` и `FAIL=0`.

## 2. Шаблон A: ТЗ на пакетный перевод словаря / JSON

```markdown
# ТЗ: Пакетный перевод <Название блока> (OpenCode)

## Цель
Перевести недостающие строки из `scratch/missing_to_translate.json` (категория `<UI|ConfigTooltips|CalcBreakdown>`) и интегрировать в `<src/Data/...>`.

## Ограничения (СТРОГО)
1. Не менять английские ключи JSON и не изменять файлы в `src/Modules/Calc*.lua`.
2. Кодировка: UTF-8 без BOM.
3. Сохранять все плейсхолдеры (`%d`, `%.2f`, `%s`, `{0}`) и цветовые теги (`^7`, `^8`, `^xRRGGBB`).
4. Для строк сайдбара использовать компактные сокращения (<= 180 px).
5. Не перезаписывать существующие ручные сокращения в `UITranslationsRU.lua`.

## Порядок работы
1. Сделать бэкап целевого `.lua` в `Snapshots/<task>-YYYYMMDD/`.
2. Заполнить переводы и вшить их в `src/Data/<Target>.lua` (формат `["EN"] = "RU"`).
3. Проверить синтаксис и качество.

## Критерии приёмки (в `host.exe` из `src/`)
- `tools/ru_i18n/validate_ru_dicts.lua` -> `ERRORS=0 WARNINGS=0`.
- `tools/ru_i18n/headless_audit_ru.lua` -> снижение `HEADLESS_MISSES`.
- `scratch/verify_final_all.lua` -> `SYNTAX: 16/16 OK`.
```

## 3. Шаблон B: ТЗ на правку Lua UI / рендера / тултипа

```markdown
# ТЗ: Исправление UI / рендера в <ИмяМодуля.lua>

## Проблема
<Точное описание бага + ссылка на скриншот или строку кода `file:line`.>

## Контракт и границы
- Разрешено менять: `src/Classes/<File>.lua`, `src/Data/UITranslationsRU.lua`.
- Запрещено: менять расчётные формулы, ломать режим `EN` (`main.uiLanguage == "EN"` должен возвращать 100% оригинальный английский вид).

## Требования к реализации
1. Учесть все 3 режима `itemLanguage` (`EN`, `RU`, `DUAL`) и оба режима `uiLanguage` (`RU`, `EN`).
2. Проверить переполнение по ширине (`DrawStringWidth`) и высоту при малом разрешении экрана.
3. Обернуть необязательные загрузки модулей в `pcall`.

## Критерии приёмки
- Написать/дополнить тест в `scratch/verify_*.lua` под этот баг.
- Прогнать `verify_final_all.lua` + `validate_ru_dicts.lua` в `host.exe` -> 100% PASS.
```

## 4. Шаблон C: ТЗ на изменение хоста (C++ SimpleGraphic / будущий C# WinUI 3)

```markdown
# ТЗ: Изменение графического хоста (<Функция / API>)

## Контракт Lua <-> Host
- Сигнатура в `src/_SimpleGraphic.def.lua`: `<описание параметров и возвращаемых значений>`.
- Обратная совместимость: при отсутствии новой функции в старом DLL Lua-слой обязан безопасно деградировать (fallback через проверку `if SetSomething then ... end`).

## Требования
1. Не менять публичные контракты существующих `DrawString` / `DrawImage` / `SetViewport`.
2. Собрать `RelWithDebInfo / x64`, сверить SHA256 DLL, развернуть в `runtime/` и `smoke/`.
3. Провести дымовой запуск приложения и проверить отклик из Lua.
```
