# Техническое Задание (ТЗ) для OpenCode / Nemotron: Полная локализация интерфейса Path of Building PoE 2

## 1. Введение и общие цели проекта

**Проект:** Path of Building Community Fork для Path of Exile 2 (PoB2).  
**Цель:** Обеспечить 100% покрытие русского перевода всех элементов пользовательского интерфейса, базы предметов, модификаторов, дерева пассивных умений и системных сообщений, гарантируя:
1. **Визуальную целостность UI:** отсутствие обрезания строк (clipping/overflow), выпадения за границы экранов, наложения текста.
2. **Типографическую стабильность:** единый базовый уровень (baseline alignment) между кириллицей и цифрами/латиницей, поддержка шрифтов Fontin и Noto Sans.
3. **Безопасность движка (Safe Display Layer):** перевод строго на уровне отображения (Display-Only). Внутренние идентификаторы (`node.id`, `mod.name`, `item.baseName`, формулы расчёта `Calcs`, формат сохранения билдов `XML`) **не должны изменяться ни при каких обстоятельствах**.

## 2. Архитектура локализации в кодовой базе

Система локализации состоит из четырёх модулей данных и одного шрифтового модуля:

```
src/
├── Data/
│   ├── UITranslationsRU.lua   -- Строки интерфейса, вкладок, кнопок, настроек, тултипов
│   ├── ItemNamesRU.lua        -- Базы, уники, редкие формулы предметов, самоцветы, флаконы
│   ├── ModTranslationsRU.lua   -- Модификаторы предметов и пассивного древа (шаблоны)
│   ├── TreeNodesRU.lua        -- Названия умений и нодов дерева пассивок (по ID и имени)
│   ├── ui_strings_flat.json   -- Плоский словарь для инференса Nemotron
│   └── ui_strings_ru.json     -- Переведённый массив строк UI
└── Modules/
    └── UIFont.lua             -- Переключение шрифтовых пресетов (Fontin / Noto Sans)
```

## 3. Требование №1: Учёт ширины русского текста (Width Budget & Anti-Overflow)

Русский текст длиннее английского аналога в среднем на **25–45%**. В фиксированных элементах UI PoB2 это приводит к обрезанию текста.

### 3.1. Жесткие ограничения колонок и элементов

| Элемент UI | Допустимая ширина | Решение / Правило сокращения |
| :--- | :--- | :--- |
| **Сайдбар: Название стата** | $\le 180\text{ px}$ | Использовать общепринятые сокращения (`Скор. передвижения`, `Эфф. запас здоровья`, `Трата маны/с`, `% брони от древа`, `Свободный дух`). |
| **Кнопки навигации верхние** | $\le 70\text{ px}$ | `<< Назад`, `Сохранить`, `Сохр. как`, `Опции`, `О программе`. Не писать длинно «Сохранить текущий билд как...». |
| **Кнопки вкладок сайдбара** | $\le 72\text{ px}$ | `Древо`, `Умения`, `Предметы`, `Расчёты`, `Группа`, `Сравнение`. Длинная вкладка `Import/Export` $\rightarrow$ `Импорт/Экспорт` (134 px). |
| **Метки слотов экипировки** | $\le 100\text{ px}$ | `Оружие 1/2`, `Доспех`, `Шлем`, `Перчатки`, `Обувь`, `Амулет`, `Кольцо 1/2`, `Пояс`, `Оберег 1..3`, `Флакон 1..2`, `Гнездо #1..#6`. |
| **Выпадающие списки (DropDown)** | $\le 220\text{ px}$ | При составных названиях редких предметов использовать лаконичный порядок: `Суффикс Префикс, База` (например, `Гибельный взрыв, Тяжёлый молот`). |
| **Карточки тултипов предметов** | $\le 450\text{ px}$ | Вторичная карточка Side-by-Side жёстко ограничена капом 450 px (`maxCardWidth`). Не раздувать строки описания. |

## 4. Требование №2: Дерево пассивных умений (Passive Tree Localization)

### 4.1. Категории нодов дерева
1. **Ключевые умения (Keystones):** крупноформатные знаковые ноды (например, `Chaos Inoculation` $\rightarrow$ `Иммунитет к хаосу`, `Zealot's Oath` $\rightarrow$ `Обет фанатика`).
2. **Значимые умения (Notables):** средние ноды (например, `Heart of the Well` $\rightarrow$ `Сердце Колодца`).
3. **Обычные умения (Basic / Normal):** малые ноды характеристик (`+10 to Strength` $\rightarrow$ `+10 к силе`).
4. **Умения Восхождения (Ascendancy):** классовые специализации.
5. **Гнёзда для самоцветов (Jewel Sockets):** `Гнездо для самоцвета`.

### 4.2. Механизм отображения и двуязычный поиск
- В модуле `src/Classes/PassiveTreeView.lua` реализована интеграция с `TreeNodesRU`:
  - **Режим DUAL (по умолчанию):** сверху крупно русское название, под ним серым цветом (`^8`) оригинальное английское название.
  - **Режим RU:** строго русское название.
  - **Поиск по древу (Tree Search):** строка поиска должна находить нод **как по русскому названию, так и по английскому** (через функцию `TreeNodesRU:Get(node)`).
- **Модификаторы нодов:** строки из `node.sd` транслируются через `ModTranslationsRU:Translate(line)`.

## 5. Требование №3: Шрифты и выравнивание базовой линии (Font Pipeline)

### 5.1. Шрифтовые пресеты (`UIFont.lua`)
- **Пресет «authentic» (Fontin):** оригинальный стиль PoE с подключенным кириллическим fallback через Noto Sans.
- **Пресет «noto» (Noto Sans):** чистый современный sans-serif с полной поддержкой UTF-8 без смещения глифов.

### 5.2. Правила рендеринга текста
- Не смешивать размеры шрифтов внутри одного текстового блока без явного пересчёта высоты строки.
- Учитывать, что в строках с цифрами кириллические заглавные буквы должны совпадать по высоте с заглавными латинскими буквами и цифрами (исправлено в DLL рендерера `SimpleGraphic.dll`).

## 6. Требования к переводу (Инструкция для Nemotron / OpenCode)

При генерации файла `src/Data/ui_strings_ru.json` модель обязана строго соблюдать следующие правила:

### 6.1. Что переводить:
- Все человекочитаемые надписи, метки, заголовки, списки, сообщения об ошибках, предупреждения и подсказки (Tooltips).
- Терминология должна строго соответствовать официальной русскоязычной версии **Path of Exile 2**:
  - *Armour* $\rightarrow$ Броня
  - *Energy Shield* $\rightarrow$ Энергетический щит
  - *Evasion Rating* $\rightarrow$ Уклонение
  - *Spirit* $\rightarrow$ Дух
  - *Unreserved Spirit* $\rightarrow$ Свободный дух
  - *Effective Hit Pool (EHP)* $\rightarrow$ Эфф. запас здоровья
  - *Stun* $\rightarrow$ Оглушение
  - *Freeze / Chill / Shock / Ignite* $\rightarrow$ Заморозка / Охлаждение / Ошеломление / Воспламенение
  - *Bleed / Poison* $\rightarrow$ Кровотечение / Яд
  - *Corrupted Blood* $\rightarrow$ Осквернённая кровь

### 6.2. Что ЗАПРЕЩЕНО изменять:
1. **Кодовые фрагменты Lua:** если ключ содержит синтаксис Lua (`self.`, `controls.`, `function`, `end`, `local`, `t_insert`), значение **должно оставаться пустой строкой `""`**!
2. **Служебные теги и цветовые коды:** префиксы цвета `^0`..`^9`, `^xRRGGBB` должны оставаться нетронутыми в начале или середине строки.
3. **Плейсхолдеры:** символы `#`, `%d`, `%s`, `{0}`, `{1}` сохранять в точности.
4. **Специальные символы разметки:** `\n`, `\t`, `:`, `/`, `(`, `)`.
5. **Внутренние ключи JSON:** ключи JSON-объекта менять нельзя! Перевод пишется только в значение `value`.

## 7. Формат обмена данными с OpenCode

### Входной файл:
`src/Data/ui_strings_flat.json` — плоский JSON:
```json
{
  "Movement Speed Modifier": "",
  "Effective Hit Pool": "",
  "Trade for these items": "",
  "Socket #1": ""
}
```

### Выходной файл:
`src/Data/ui_strings_ru.json` — плоский JSON с переводами:
```json

  "Trade for these items": "Купить эти предметы",

```
